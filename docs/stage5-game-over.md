# 코어 패배와 다시 시작

작업일: 2026-09-18. 브랜치: `feature/Min`.

## 동작

- 코어 체력이 0 이하가 되면 `Core`가 `GameManager.EndGame()`에 패배를 한 번만 전달한다. 기존 방어력 계산은 유지한다.
- 기존 페이즈 enum 마지막에 `Defeated`를 추가한다. 패배 이후 Q, 방어 완료, 페이즈 변경으로 날짜를 진행할 수 없다.
- 건설·연구 메뉴와 미리보기를 정리한 다음 플레이어 조작, 적 AI, 건물 스크립트를 멈추고 게임 시간을 정지한다. 패배 UI는 계속 동작한다.
- 기존 `GameplayHUD` 프리팹에 패배 문구와 다시 시작 버튼을 추가한다. 부모 HUD가 입력을 받지 않는 설정이므로 패배 패널에만 별도 CanvasGroup으로 클릭을 허용한다.
- 버튼을 누르면 Main 로딩을 먼저 준비한다. 준비가 끝나면 이전 플레이어·자원 인벤토리·건설 건물을 제거하고, 삭제가 끝난 다음 새 Main을 활성화한다. GameManager는 유지하면서 Day 1 수집 단계로 초기화한다.
- 일반 채집 완료 기록, 일일 자원 스포너 기록, 상호작용 선택 기록을 새 게임에서 초기화한다. 새 플레이어 생성으로 체력과 연구 UI의 레벨 값도 씬 초기값으로 돌아간다.
- 버튼 중복 실행을 차단한다. 대상 씬이 없으면 기존 상태를 유지하고 다시 시도할 수 있는 문구를 표시한다.

## 범위

새 게임 스크립트를 만들지 않고 기존 Core, GameManager, GameHUDStatusUI, ResourceNode, DailyResourceSpawner, InteractionSelection을 확장했다. 기존 HUD와 전용 한글 폰트에 패배 화면 및 필요한 글자를 추가했다.

평소 Main/Collection 왕복에서 자원·건물·채집 상태를 유지하는 동작은 그대로 둔다. 플레이어 피격·사망, 승리 조건, 타이틀 복귀, 디스크 저장/불러오기, 밸런스 변경은 이번 범위가 아니다. 현재 빌드 씬에 없는 생존자 구출/명단 시스템은 수정하지 않았으며, 추후 빌드 씬에 연결할 때 새 게임 초기화 대상에도 포함해야 한다.

## 검증

Unity Main의 실제 Play에서 함수 및 버튼 이벤트 호출로 검사했다. 물리 키보드/마우스 입력 검사는 포함하지 않는다.

- 채집·건설 후 평소 씬 왕복에서 자원, 소모한 채집 지점, 건물 체력 유지.
- 건설 메뉴를 연 상태에서 코어 파괴: 메뉴 닫힘, 조작 및 전투 정지, 패배 UI 표시, 진행 재진입 차단.
- 건설 미리보기를 띄운 상태에서 패배하면 미리보기와 건설/철거 모드가 정리됨.
- 패배 버튼 위치의 UI 레이캐스트, 한글 글리프 및 텍스트 넘침 검사.
- 잘못된 재시작 씬 이름에서 현재 세션을 보존하고 다시 시도 가능.
- 버튼 연속 호출에도 한 번만 재시작. 플레이어·HUD·GameManager·인벤토리 중복 없음.
- 날짜, 플레이어·코어 체력, 자원, 연구 레벨, 건물, 적 초기화.
- 새 게임에서 일반·일일 자원 4개 복구 및 첫날 자원 종류 복구. 이후 다시 채집하면 같은 날 재입장 시 채집 상태 유지.
- 재시작 후 적 생성 및 방어 종료로 Day 2 진행.
- 연구 UI가 시간을 멈춘 상태에서 패배 처리 후 두 번째 재시작 성공.

패배 패널의 부모 HUD가 클릭을 차단하던 문제를 보완했다. 이후 발견한 Main 무기의 빈 availableFireModes 목록은 사용자 승인 후 단발·연발·점사로 연결했다. Weapon.cs와 공격력·발사 간격은 변경하지 않았다. 씬 저장 시 기존 GameManager의 재시작 대상 기본값 `01_Main`도 직렬화되었다.

최종 전체 검사에서 위 기능 항목 모두 통과했고, 재시작 두 번을 포함한 검사 구간 Error/Exception은 0개였다. 별도 무기 검사에서는 첫 Main 시작과 재시작 후 각각 단발→연발→점사→단발 전환, HUD 표시, 발사 간격, 단발 1회·연발 2회·점사 3회의 테스트 표적 레이캐스트 적중을 확인했다. 모드 전환은 V키가 호출하는 메서드를 직접 실행했으며, 물리 V키/마우스 입력 및 적에게 주는 피해량 검사는 포함하지 않는다. 다시 시작 버튼은 Unity 포인터 클릭 이벤트로도 동작을 확인했다.

검사 코드·결과·캡처는 프로젝트 밖 로컬 임시 폴더의 `DefeatChecks.cs`, `DefeatChecks-result.json`, `DefeatScreen.png`, `WeaponModeChecks.cs`, `WeaponModeChecks-result.json`에 있다. 자동 커밋·푸시는 하지 않는다.

## 씬 전환 보완 및 통합 검증 (2026-09-25)

- 준비 완료는 Main의 수집 단계에서만 허용한다. Collection에서는 Q 입력이 호출하는 함수도 차단하고 HUD의 Q 안내를 숨긴다.
- Main 코어가 제거될 때 현재 체력을 GameManager에 보관하고, Main에 돌아오면 복원한다. 새 게임을 다시 시작할 때 저장값을 초기화하며, 이전 코어가 제거되면서 값을 덮어쓰지 않도록 한다.
- 밤 시작·방어 중에는 Main → Collection 이동을 차단하고 기존 상호작용 UI에 이유를 표시한다. 낮의 양방향 이동과 Collection → Main 귀환은 허용한다.
- 수정 전 밤 포털 왕복에서 기존 적·스포너 제거 및 네 스포너의 웨이브 2 → 1 초기화를 재현했다. 수정 후 이동 시도에도 적·웨이브가 유지되고 다음 날 출입 제한이 해제되는 것을 확인했다.
- 별도 코어 검사에서 피해 후 60, 회복 후 80이 왕복 후에도 유지됐다. Day 2에도 80을 유지했고 재시작 후 Day 1·체력 100으로 복구됐다.

Intro부터 시작하는 연속 Play 검사도 통과했다. 시작 버튼과 재시작 버튼은 UI 레이캐스트 및 포인터 클릭 이벤트로 실행했으며, 포털과 채집은 상호작용 선택을 거쳐 기존 함수를 호출했다. 채집 시간, 자원 지급량, 건설 비용, 적 스폰 간격·수·웨이브 설정은 변경하지 않았다. 적은 피해 함수를 호출해 처치했으므로 수동 사격, 전투 난이도와 조작감은 검증 범위에 포함하지 않는다.

1. 시작 재화 0에서 첫날 채집으로 목재 40·금속 60·식량 10·희귀 금속 35를 획득했다.
2. 철제 벽 미리보기·회전·설치 후 목재 15·금속 40이 정확히 차감됐다.
3. 같은 날 왕복 시 채집한 자원이 다시 나타나지 않았고, 벽 체력 195·코어 체력 60과 보유 자원이 유지됐다.
4. 기본 5웨이브의 예정된 적 100마리 처치 후 Day 2로 정상 진행했다.
5. Day 2에 일일 스포너 3곳이 각각 전날과 다른 자원을 생성했고 다시 채집할 수 있었다. 일회성 자원은 소진 상태를 유지했다.
6. 코어 파괴 후 패배 화면에서 다시 시작하자 Day 1·코어 체력 100·재화 0으로 초기화됐다. 이전 플레이어·건물은 제거됐고 새 플레이어·HUD·GameManager의 중복도 없었다.
7. 새 게임의 Collection에서 자원 4개와 첫날 자원 종류가 복구됐으며 Main 귀환도 정상 동작했다.

통합 검사 구간 Error/Exception은 0개였다. 결과는 프로젝트 밖 임시 폴더의 `FullLoop-result.json`에 기록했다. 검증 후 Play를 종료하고 Main을 다시 열었으며 임시 연결 패키지는 제거했다.
