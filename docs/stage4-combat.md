# 4단계 전투 연결 점검

## 작업 범위

- 플레이어 피격 처리는 강철님 담당으로 남겨 둔다.
- 이번 작업은 Main에서 스폰된 적이 움직이지 않는 문제를 해결한다. 기존 적 AI 스크립트와 팀원 테스트 씬은 변경하지 않는다.

## Main 적 이동 문제 (2026-09-14)

- Main 스포너 4개는 모듈 분리 전 데이터가 남은 `Enemy.prefab`을 사용했다. 체력·이동·공격 수치가 옛 EnemyAI 항목에만 있고, 기지 공격 행동 컴포넌트도 없었다.
- 수정 전 Play 측정: 4곳 모두 NavMeshAgent는 NavMesh에 올라갔으나 실제 속도 0, 체력 0, EnemyBaseAttackBehaviour 없음, 이동 경로 없음이었다. 5초 동안 수평 이동이 없고 바닥에 맞추는 높이 보정만 발생했다.
- `MainEnemy.prefab`을 별도로 만들고 Main 스포너 4개에 연결한다. 기존 Enemy.prefab은 jim01/tie0 테스트 씬에서도 사용하므로 보존한다.
- 기존 수치를 각 모듈에 반영: 체력 30, 이동 속도 3.5, 공격 거리 1.5, 공격력 10, 공격 간격 1.5초, 마비 최대 누적 100 및 방어 1.
- 기존 EnemyBaseAttackBehaviour와 BuildingAttackSlotManager를 연결하고 PlayerWall/PlayerTower 등 프로젝트 레이어를 지정한다. 탐지/이탈 거리는 기존 RangeEnemy 설정과 같은 8/12를 사용한다.
- NavMesh 재생성, 스폰 위치 변경, 적 스크립트 수정은 하지 않는다.

## 검증

- 실제 Main 스포너 4개의 기존 SpawnEnemy 함수를 호출한 뒤 정상 AI/행동/NavMeshAgent 갱신으로 5초간 이동을 측정했다. 강제 Warp나 SetDestination은 사용하지 않았다.
- 수정 후 4곳 모두 약 13.46~16.01m 이동했고 속도 3.5, 체력 30, 기지 공격 행동이 적용됐다. 검사 중 Error/Exception은 0개였다.
- 전체 웨이브, 모든 건물 공격/파괴, 플레이어 피격은 이번 검증 범위가 아니다.
- 로컬 임시 결과: `MainEnemyMovement-before.json`, `MainEnemyMovement-after.json`.

## 코어·벽·타워 전투 확인 (2026-09-14)

- 코어 공격 실패를 재현했다. 적은 코어 표면에서 약 2.20 떨어진 목적지에 도착했지만 공격 거리는 1.5여서 체력이 100에서 줄지 않았다.
- `MainEnemy.prefab`의 NavMeshAgent 정지 거리를 1에서 0.1로, EnemyBaseAttackBehaviour의 목표점 추가 거리를 1에서 0으로 조정했다. 공격 거리·공격력·속도와 기존 팀원 스크립트는 변경하지 않았다.
- 수정 후 Main의 스포너 4곳에서 생성한 적 모두 정상 AI로 접근해 각각 코어를 공격했다. 표면과의 거리는 약 1.20~1.37이었고 코어 체력은 100에서 80으로 감소했다. 별도의 단일 적 검사에서도 100에서 95로 감소했다(공격력 10, 코어 방어력 5).
- 기관총 타워의 기존 공격으로 적 체력이 30 → 20 → 10으로 감소하고 적 오브젝트가 제거됐다. 타워는 생존했다.
- 기존 벽 프리팹 12개를 Play 중 코어 주변에 닫힌 형태로 배치해 경로를 차단했다. 일반 적이 벽을 타깃으로 선택하고 7 피해를 줬으며 코어 체력은 유지됐다. 변경 후 설정에서도 다시 통과했다.
- 벽의 기존 체력 99,999는 유지했다. 벽 파괴까지 기다리는 검사, 열린 경로에서의 우회 검사, 다른 타워 종류, 전체 웨이브·패배·재시작, 플레이어 피격은 이번 통과 범위가 아니다.
- 검사는 Main의 기존 SpawnEnemy 함수와 실제 프리팹을 사용한 프로그램 실행이다. 코어·벽에 피해 함수를 직접 호출하거나 적에게 목표를 강제 지정하지 않았다. 테스트 건물·적은 제거하고 코어 체력은 검사 전 값으로 복원했다. 검사 중 Error/Exception은 없었다.
- 로컬 임시 결과: `MainCombatChecks-before-core-fix.json`, `MainCombatChecks-result.json`, `MainCoreDirectionsCheck-result.json`, `MainWallCombatCheck-result.json`.

## 다수 적의 대기·경로 재개 확인 (2026-09-14)

- Main Play에서 밤 단계로 전환하고 기존 스포너 4개의 정상 갱신으로 첫 웨이브 20마리(각 5마리, 생성 간격 3초)를 생성했다. 20마리 모두 NavMesh에 올라갔으며, 관찰 시점에 15마리가 코어를 공격하고 5마리가 뒤에서 대기했다.
- 앞의 적 15마리를 기존 TakeDamage 함수로 처치한 뒤 대기하던 5마리 모두 새로 코어 공격을 시작했다. 이번 조건에서는 앞의 적 때문에 잠시 기다리는 상태가 영구적인 멈춤으로 이어지지 않았다.
- 기존 벽 프리팹 12개로 코어 주변 경로를 닫고 스포너의 SpawnEnemy 함수로 8마리를 생성했다. 그중 4마리의 벽 공격과 벽 3개의 체력 감소를 확인했다.
- 기존 BuildingSystem.TryRemoveBuilding으로 벽을 철거한 후 8마리 모두 정상 AI로 코어에 도달해 공격을 재개했다. 검사 중 Error/Exception은 0개였다.
- 긴 관찰을 위해 Play 중에만 코어 최대/현재 체력을 10,000으로 올렸으며, 종료 시 원래 값으로 복원하고 테스트 적·벽을 제거했다. Play도 종료해 웨이브 상태를 초기화했다. 이번 검사로 게임 스크립트·프리팹·씬 설정을 추가 변경하지 않았다.
- 적 처치는 테스트 코드의 피해 호출이며 플레이어 무기 조작 검사가 아니다. 철거는 기존 함수를 실행한 것으로 X키·마우스 선택 입력은 이번에 검사하지 않았다. 첫 웨이브와 지정한 폐쇄 벽 배치에서의 결과이며, 전체 5웨이브·날짜 전환·모든 배치의 군중 이동까지 검증한 것은 아니다.
- 로컬 임시 결과: `MainCrowdChecks-result.json`.
