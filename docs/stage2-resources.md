# 2단계: 자원과 수량 표시

현재 추가 사항: 빨간 표시 3곳은 아래의 날짜별 스포너 규칙을 사용한다. 이전 4종 검사에서 기록한 영구 소진 규칙은 기존 고정 목재 노드에만 계속 적용된다.

사용자 확정: 목재, 금속, 희귀 금속, 식량 4종. 앞서 언급한 부품은 희귀 금속을 의미한다. 기존 씬의 enum 값과 호환되도록 Wood=0, Metal=1, Food=2를 유지하고 RareMetal=3을 추가했다.

## 구현된 코드

- ResourceInventory: 기존 Add/Get과 씬 간 유지 구조를 유지하고 Changed 이벤트, CanAfford, TrySpend를 추가했다. 모든 자원이 충분할 때만 일괄 차감하고 마지막에 UI 변경을 한 번 알린다. 음수 비용과 잘못된 자원 종류, null 비용은 거부한다.
- ResourceNode: 인벤토리가 연결되지 않았을 때 지급 없이 노드가 사라지는 문제를 막는다. 채집 시간·기본 수량·채집가 보너스는 유지한다.
- ResourceCounterUI: 이름·수량만 표시하는 별도 컴포넌트다. 데이터 변경 알림을 구독하고 비활성화 시 구독을 해제한다. 추후 UI 교체 시 자원 로직을 바꾸지 않고 표시만 교체할 수 있다.

## 현재 검증 상태

- 전체 게임 C# 소스를 Unity 참조 어셈블리로 오프라인 컴파일: 오류 0, 기존 obsolete API 경고 8.
- 실제 ResourceInventory 소스와 최소 Unity 수명주기 대역으로 동작 검사 22개 통과: 4종 지급, 기존 enum 값 보존, 부족 시 부분 차감 방지, 성공 시 정확한 차감, 최종 잔액 알림, 무효 비용 거부, 음수 잔액 방지.
- 후속 작업에서 Main 인벤토리·수량 UI 연결과 Collection 기존 표시의 4종 채집 기능을 연결했다. 아래 실제 배치 검증까지 완료했다. 직접 입력과 경로 이동, 최종 자원 수치 조정은 별도 확인 사항이다.
- 건설 비용의 실제 사용처 연결은 3단계다. 저장 파일과 재실행 시 복원도 이번 범위에 포함하지 않는다.

## 자원 UI 방향 제안

- 상단 우측에 `목재 120 | 금속 80 | 희귀 금속 5 | 식량 30`의 순서로 한 줄 표시한다. 기존 중앙 나침반과 조준 영역은 비운다.
- 구현 확인용은 이름과 수량만 사용한다. 최종 디자인에서 작은 실루엣 아이콘, 흰색 숫자, 옅은 어두운 배경을 더한다. 큰 테두리나 장식 패널은 두지 않는다.
- 목재는 따뜻한 갈색, 금속은 회색, 희귀 금속은 낮은 채도의 보라색, 식량은 낮은 채도의 녹색을 보조색으로 제안한다. 색만으로 구별하지 않고 이름과 아이콘을 함께 둔다.
- 자원 획득 시 해당 숫자 근처에 `+10` 같은 짧은 표시만 보여준다. 여러 알림이 화면 중앙을 가리지 않게 한다. 이 효과는 아직 구현하지 않았다.
- 건설 화면에서는 선택한 비용을 `보유 / 필요`로 표시하고 부족한 항목만 강조한다. 이는 건설 단계에 적용할 제안이다.
- 이번 단계의 수량은 씬 왕복 중 유지되는 공용 보유량이다. 무게 제한·가방 슬롯·사망 시 손실은 별도 규칙 합의 없이 추가하지 않는다.

## Main 화면 연결 및 실제 플레이 검증

- UI가 보이지 않았던 원인은 표시용 스크립트만 있고 씬 오브젝트와 인벤토리 연결이 없었기 때문이다.
- Main에 독립된 ResourceInventory 오브젝트를 추가하고, 기존 플레이어 Canvas의 `ResourceCounter`에 네 자원의 이름과 수량을 연결했다. 배치는 상단 우측이며 기존 게임 HUD와 나침반은 유지한다.
- 실제 1920×1080 Game View에서 네 자원 `목재 0 / 금속 0 / 희귀 금속 0 / 식량 0`이 보이는 것을 확인했다.
- Unity Play 통합 검사 27개 통과: 네 자원 지급 시 즉시 표시, 부족한 복합 비용의 전체 차감 거절, 충분한 비용 차감과 표시 갱신, 기존 Collection 노드의 실제 프레임 채집, Main 귀환 시 네 자원 수량과 원래 인벤토리·UI 유지.
- 테스트에서는 목재 27, 금속 20, 희귀 금속 18, 식량 20이 표시됐으며 검사 구간의 오류 로그는 없었다. 이는 임시 Play 데이터로, 테스트 종료 시 Play를 중단해 정리했다.
- 직접 키보드 E 입력 대신 선택·시작·포털 로드 메서드를 호출했다. 목재 외 세 종류는 지급 API로 검사했으며, 해당 채집 노드의 실제 씬 배치는 다음 작업이다.

## Collection 머티리얼 복구 및 실제 4종 채집 검증

- 분홍색 표시 원인: master에서 feature/Min으로 작업을 옮길 때 Collection이 참조하는 Black/Red/White 머티리얼이 Min에 없었는데 의존 에셋까지 보존하지 못했다. 해당 `.mat`와 원래 `.meta` 6개 파일만 master에서 복원했다. 브랜치 전환·병합은 하지 않았다.
- 수집 씬의 렌더러 39개를 검사해 머티리얼 누락 0, 오류·미지원 셰이더 0을 확인했고 Scene View 캡처에서 정상 색상을 확인했다.
- 사용자가 확인한 기존 빨간 표시는 스포너가 아니라 기능 없는 배치 표시였다. 이 세 오브젝트에 ResourceNode를 추가하고 위치·이름·외형은 유지했다.
- 기존 목재 `채집점` (11.87, 0, -3.15)은 유지했다. 빨간 `채집점` (10.18, 0.09, -21.49)은 금속, `채집점 (1)` (-13.91, 0.09, -4.2)은 식량, `채집점 (2)` (-52.18, 0, -33.53)은 희귀 금속으로 연결했다.
- 세 노드의 감지 거리·플레이어 레이어·채집 시간·수량은 기존 목재 노드 설정을 그대로 사용했다. 현재 4종 모두 3초·10개이며 최종 밸런스 수치로 확정한 것은 아니다.
- 실제 배치 노드로 Unity Play 검사 34개 통과: 종류별 상호작용 선택, 진행바, 범위 이탈 취소, 재시작, 정확한 지급, 해당 자원 UI 갱신, 귀환 후 수량 유지, 재진입 시 이미 수집한 4개 노드 비활성화와 중복 지급 방지. 결과 수량은 종류별 10개, 검사 중 오류 로그는 0이었다.
- 테스트에서는 플레이어 위치 이동과 시작·포털 메서드 호출을 코드로 수행했다. 각 지점까지 걸어가는 경로와 실제 E키 입력은 검증하지 않았다. Play 종료로 테스트 수량을 정리하고 Collection 씬을 편집 모드로 열어두었다.

## 빨간 표시 3곳의 날짜별 스포너 (2026-09-11)

- 사용자 요청에 따라 `DailyResourceSpawner.cs`를 추가하고 세 빨간 표시의 부모로 연결했다. 자원 오브젝트가 채집 후 비활성화되어도 부모 스포너가 날짜를 감지한다. 원래 표시의 월드 위치·이름·외형·콜라이더·3초 채집·10개 지급은 유지했다.
- Day 1은 기존 금속·식량·희귀 금속 배치를 사용한다. 이후 각 지점은 목재·금속·식량·희귀 금속 중 전날과 다른 종류를 독립 추첨한다. 서로 다른 지점에서 같은 종류가 나올 수 있다.
- 지점별 하루 한 번 채집한다. 같은 날 씬 왕복 시 종류와 소진 상태를 유지한다. 다음 날에는 채집했든 남겨뒀든 새 종류로 교체된다. Collection 밖에서 며칠을 보내도 현재 날짜까지 반영한다.
- 기존 `GameManager.currentDay`를 읽는다. GameManager의 날짜·방어 진행 코드는 이번에 변경하지 않았다. 날짜는 기존 방어 완료 흐름에서 증가한다.
- ResourceNode에는 선택적 스포너 참조, 스포너 소유 노드의 소진 상태 위임, 날짜 경계의 지급 방지 검사만 추가했다. 날짜가 넘어가면 진행 중 채집은 취소되고 새 자원을 다시 채집할 수 있다. 기존 고정 목재는 이전의 1회 채집 규칙을 유지한다.
- 스폰 상태는 현재 플레이 세션의 메모리에 유지한다. 게임을 완전히 종료했다 다시 켜는 저장/불러오기는 포함하지 않는다. 자원별 모델 교체도 아직 하지 않았다.
- Unity 참조 어셈블리로 전체 게임 소스 컴파일: 오류 0, 기존 obsolete 경고 8. 실제 편집기에서도 새 스크립트 로드 확인.
- 실제 Unity Play 검사 42개 통과: 실제 4종 채집과 정확한 지급, 같은 날 소진/미소진 상태 및 종류 유지, Main에서 방어 완료로 Day 2 전환, 각 지점의 전날과 다른 종류 재생성, Collection 내 Day 3 전환과 진행 취소/무지급, 며칠 건너 Day 5 재방문, 고정 목재의 기존 동작, 단일 인벤토리 유지. 검사 구간 Error/Exception 0.
- 검사는 실제 배치 노드와 프레임, 기존 포털 및 방어 완료 메서드를 사용했다. 물리 E키 입력과 걸어서 이동하는 경로 검사는 별도다. 결과는 `Temp/DailyResourceSpawners-test-result.json`에 남겼다.
- Play를 종료하고 저장된 Collection을 다시 열어 세 자원이 활성 상태이며 월드 위치·수량이 유지됐고 오류 머티리얼이 0개임을 확인했다. `feature/Min`에서 작업했으며 커밋·푸시는 하지 않았다.
