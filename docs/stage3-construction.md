# 3단계 첫 작업: 건설 카드와 비용 연결

확인일: 2026-09-12. 브랜치 `feature/Min`, 기준 커밋 `b31df90`.

## 문제와 수정 범위

Main의 BuildQuickUI에 카드 9개가 있었지만 모든 buildPrefab과 buildingSystemObject 참조가 비어 있었다. UI가 SendMessage로 호출하는 StartPlacement는 BuildingSystem에 없었다. B키의 기존 건설은 비용 없이 Instantiate만 호출했다.

- 신규 `BuildCost.cs`: 네 자원의 실제 비용과 표시 문자열을 같은 데이터에서 제공한다. configured가 false인 미설정 비용과 음수 비용을 거절한다.
- `BuildItem.cs`: cost 필드 하나를 추가한다. 기존 이름·설명·아이콘·프리팹 필드는 유지한다.
- `BuildCardUI.cs`: 실제 비용을 표시하고 프리팹 없는 카드는 `준비 중` 및 비활성 버튼으로 남긴다.
- `BuildQuickUI.cs`: 실제 BuildingSystem.StartPlacement를 호출한다. 메뉴를 열 때 미리보기를 정리하고 조작을 멈추며, 닫을 때 각 스크립트의 열기 전 enabled 상태를 복원한다.
- `BuildingSystem.cs`: 카드와 기존 B/1/2/3 경로가 동일한 비용 데이터를 사용한다. 바닥·회전·겹침·잔액을 배치 직전에 다시 검사하고, 비활성 상태로 생성한 뒤 비용 차감에 성공하면 실제 건물을 활성화한다. 같은 프레임의 중복 생성도 차단한다. 메뉴 선택 클릭이 곧바로 건설 입력으로 이어지지 않게 한다.
- 미리보기 복제본은 기존 렌더러와 재질 표시·회전을 유지한다. 복제본의 게임 스크립트·콜라이더·NavMeshObstacle을 비활성화하고 피격 컴포넌트를 제거한다. 실제 프리팹과 건물 공격/피격 스크립트는 수정하지 않았다.
- Main 씬: 기존 카드 5개에 프리팹을 연결하고 카드 9개에 기존 표시 비용을 숫자로 옮겼다. 메뉴 제어 대상은 PlayerController, PlayerShoot, CameraFollow, BuildingSystem이다. 씬 이동 시 임시 미리보기와 건설/철거 모드가 정리된다.

BuildItem, BuildCardUI, BuildQuickUI의 기존 CP949 인코딩은 유지했다. 씬은 Unity Editor API로 편집했다. 사용자 폰트 변경은 별도로 보존한다.

## 다음 작업

건물 씬 왕복 유지와 Main의 철거 연결, 사용자 직접 조작으로 철거 및 씬 왕복 확인을 마쳤다. 환급은 팀 논의 후 진행하기로 보류하고, 다음 작업은 구현 계획의 4단계인 실제 전투 연결 점검이다.

### 기존 철거 기능 연결 확인 (2026-09-14)

- 기존 `BuildingSystem`에 X키 철거 모드, 조준 대상 재질 표시, 좌클릭 삭제가 구현되어 있다. 새 철거 스크립트는 추가하지 않았다.
- Main의 `removeRayLayer`가 0(Nothing)인 것을 실행 중인 Unity 편집기에서 확인했다. 건설 카드 5종의 Collider가 사용하는 `PlayerWall`·`PlayerTower`를 연결했다(마스크 6144).
- Unity에서 Main을 저장하면서 포털의 기존 기본 E키 값(`interactKey: 101`)과 NavMeshSurface의 자동 계산 voxel 값도 기록되었다. voxel override는 꺼져 있으며, NavMesh 데이터 재생성은 하지 않았다.
- 사용자 직접 조작 확인: 철거가 동작한다고 보고했고, 이어 요청한 Main/Collection 왕복 검사도 테스트 완료로 보고했다. 해당 검사는 철거한 건물이 다시 나타나지 않고 남긴 건물이 유지되는 흐름이다.
- 테스트 재화는 기존 `ResourceInventory.Add`로 Play 세션에만 자원 4종을 각각 1,000씩 지급했다. 시작 재화·채집량·건설 비용 코드는 변경하지 않았다.
- 준비한 자동 철거 검사 스크립트는 실행하지 않았다. 건물 5종 전체의 재질 복구·거리 제한 등 세부 항목까지 자동 검사에 통과한 것으로 기록하지 않는다.

### 철거 시 자원 환급 요구사항 (2026-09-14)

- 사용자 의견: 철거 시 건설에 사용한 자원을 일부 환급하는 기능이 필요하다.
- 진행 상태: 팀원들과 규칙을 논의한 뒤 진행한다. 환급 구현은 보류하며, 제안된 50% 비율은 확정 사항이 아니다.
- 기존 X키 철거 모드·대상 표시·좌클릭 삭제 기능을 바탕으로 추가할 예정이며, 현재 환급은 구현되지 않았다.
- 환급 비율과 계산 기준은 미정이다. 건설 당시 지불한 비용, 업그레이드 비용 포함 여부, 건물의 남은 체력 반영 여부, 자원별 소수점 처리 기준은 구현 전에 정한다.
- 이번 요청은 요구사항 기록이며, 환급 수치 확정이나 코드·씬 변경은 포함하지 않는다.

## 건설한 건물의 씬 왕복 유지 (2026-09-14)

- 새 `BuiltBuildingPersistence`가 플레이 중 완성한 건물을 원래 씬 경로별 부모 아래 보관한다. 부모는 DontDestroyOnLoad로 유지하며, 원래 씬을 떠나면 비활성화하고 돌아오면 활성화한다. 현재 Main/Collection의 Single 씬 전환을 대상으로 한다.
- `BuildingSystem.TryBuild`에서 비용 차감 성공 후에만 등록한다. 미리보기와 실패한 배치는 보관하지 않는다. 같은 건물을 재등록해도 복제하거나 다른 씬 소유로 바꾸지 않는다.
- 같은 오브젝트를 유지하므로 위치·회전·체력·업그레이드 필드가 남는다. 파괴 및 오브젝트 제거는 그대로 실제 건물을 삭제하므로 왕복해도 되살아나지 않는다. 재활성화 시 건설 비용을 다시 차감하거나 환급하지 않는다.
- 비활성 건물의 렌더링·충돌·Update는 실행되지 않는다. 건물의 OnDisable에 따른 상호작용 취소는 기존 동작을 사용한다. 절대 시간 기반 공격 쿨타임은 시간이 흐를 수 있으므로 귀환 후 기존 조건에 따라 다시 공격한다.
- `SurvivorMechanicBehaviour`는 기존에 기억한 대상이 비활성이면 놓고 다시 찾는다. 수리량·체력·방어 계산은 변경하지 않는다.
- 00_Intro 진입 시 보관한 건물을 정리한다. 게임 종료/다시 Play 시 유지하는 파일 저장과 씬에 원래 배치된 건물의 상태 보존은 포함하지 않는다. 다른 시스템의 새 게임 초기화까지 구현한 것은 아니다.
- 검증: 전체 게임 C# 컴파일 오류 0, 기존 obsolete 경고 7. 실제 Unity Main/Collection 플레이 검사 54개 통과, 검사 중 Error/Exception 0.
- 실제 카드 5종 건설·정확한 비용 차감·피격 후 Main/Collection 3회 왕복에서 동일 오브젝트의 위치·회전·체력 유지와 중복 없음, Collection에서 충돌·스크립트 비활성화, 정비공의 비활성 대상 해제, 귀환 후 수리, 파괴/오브젝트 제거 후 재등장 방지, Intro 진입 시 보관 건물 초기화를 확인했다.
- 검사는 건설·포털·피격·수리 메서드를 코드로 호출했다. 실제 키보드/마우스 조작과 철거 UI는 별도 확인 사항이다. 결과는 로컬 임시 폴더의 `LastShelterBuildingPersistenceChecks-result.json`에 보관했다.

이 작업은 자동 커밋·푸시하지 않는다. 이후 편집도 파일·수정 이유·플레이 영향을 먼저 설명하고 진행한다.
