## 실제 Unity 검증

Unity 6000.3.18f1의 열린 에디터에서 Play 모드로 실행했다. 임시 테스트 오브젝트는 씬에 저장하지 않았으며, 검증 후 Play를 종료하고 저장되지 않은 변경이 없는 원래 Intro 씬으로 돌아온 것을 확인했다.

- 상호작용 검사 25개 통과: 실제 CharacterController 거리 판정, 가까운 대상 선택, 한 프레임 중복 실행 방지, 채집·치료 중 대상 유지, 반복 호출 시 타이머 유지, 범위 이탈 시 취소, 진행바 정리, 자원 10개와 체력 30 지급, 사용 불가능한 대상 제외.
- 포털 검사 16개 통과: 포털과 자원의 우선순위, 채집 중 포털 차단, 작업 종료 후 사용 가능, 목적지가 비어 있거나 없을 때 차단, 범위 이탈·비활성화 처리, Main→Collection→Main 이동.
- 왕복 각 지점에서 플레이어 1개, 카메라 1개를 확인했다.
- 상호작용 선택 검사 구간에는 오류 로그가 없었다. 실제 게임 씬 로드 구간에서는 아래 별도 문제가 발생했다.
- 제한: 테스트 코드에서 선택 함수와 작업 시작/씬 로드 메서드를 호출했다. 실제 키보드 E 입력, 화면상의 조작감, 건설 미리보기, 전체 게임 루프, 배포 빌드는 이번 검증 범위에 포함하지 않았다.

## 실제 게임 씬에서 확인한 미해결 사항

- 플레이어에 Missing Script 1개가 있으며, 실행 중 PlayerInteractUI는 0개다. 기존 Main 씬의 PlayerInteractUI 연결 누락과 일치한다. 임시 테스트 UI는 정상 동작했지만, 실제 플레이어 UI 연결은 복구가 필요하다.
- 실행 중 ResourceInventory가 0개다. 임시 인벤토리로 자원 지급 로직을 검증했으므로 실제 씬의 자원 누적까지 검증된 것은 아니다.
- 씬 로드 시 `사격 모드 없습니다.` 오류가 발생했다.
- `MainLight 태그를 가진 오브젝트가 없습니다.` 경고가 발생했다.
- 최초 검사에서는 빌드 목록에 Intro가 없고 테스트 씬들이 포함되어 있었다. 아래 Intro 구현에서 해결했다.
- 위 문제는 이번 검증에서 수정하지 않았다. 영향과 수정 대상을 설명하고 해당 단계에서 처리한다.

## 이후 작업 절차

1. 시작 전 작업 폴더, 현재 브랜치, HEAD, 로컬 변경사항을 확인하고 알린다. `feature/Min`을 기준으로 작업하며, 다른 브랜치이면 임의로 계속하지 않는다. 브랜치 생성·전환·병합은 사용자의 요청 범위에서만 수행한다.
2. 수정 전에 대상 파일, 문제 원인, 변경할 동작, 플레이 영향, 검증 방법을 설명한다. 사용자가 승인한 작업 범위는 계속 진행하되, 다른 사람의 스크립트나 플레이 규칙으로 범위가 넓어지면 구체적인 변경안을 먼저 확인받는다.
3. 기존 스크립트는 필요한 부분만 수정한다. 단순 정리, 이름·인코딩 변경, 전체 교체를 끼워 넣지 않는다. 새 스크립트도 기존 기능과 중복되지 않는지와 씬 연결 필요성을 먼저 설명한다.
4. 사용자 씬·프리팹·폰트 변경을 보존한다. 씬 배치, 이동 목적지, 건설 미리보기 같은 플레이 요소를 버그 수정 명목으로 임의로 없애지 않는다. 패키지·프로젝트 설정 변경은 이유와 범위를 먼저 설명하고 승인된 범위만 적용한다.
5. 작은 단위로 구현한 뒤 컴파일, 해당 동작의 Play 검증, 기존 동작에 대한 영향 확인을 한다. 코드 검사·자동 호출·직접 키 입력·빌드 검증을 구분해서 결과와 남은 문제를 보고한다.
6. 커밋은 사용자가 요청한 경우에만 한다. 커밋 전에 변경 파일과 diff, 검증 결과를 확인하고 관련 파일만 선택해서 포함한다. 사용자 작업이나 임시 테스트 파일을 임의로 포함하지 않는다.
7. 푸시와 병합도 명시적으로 요청받은 범위에서만 수행한다. 커밋 요청을 푸시 허가로 간주하지 않는다. 강제 푸시나 이력 재작성은 별도 지시 없이 하지 않는다.
8. 되돌리기는 내가 만든 변경을 구분해 필요한 부분만 수행한다. 사용자 변경이 섞인 파일에 전체 초기화나 강제 복원을 적용하지 않는다.

## Intro 구현 후 검증

- `00_Intro.unity`에 기존 프로젝트 폰트를 사용한 제목, 게임 시작·종료 버튼, 로딩 안내, 조작 설명과 UI 입력 연결을 구성했다.
- 준비된 `IntroMenu.cs`를 연결했다. 시작은 기존 Main 씬을 비동기로 열며, 로딩 중 버튼을 잠근다. 종료는 에디터에서 Play를 중단하고 배포 코드에서는 Application.Quit를 호출한다.
- 빌드 목록을 `00_Intro`, `01_Main`, `02_Collection` 세 씬으로 정리했다. 테스트 씬 파일 자체는 삭제하지 않았다.
- Unity Play의 Intro 검사 16개가 통과했다. 버튼 연결, 키보드 탐색의 초기 선택, 잘못된 목적지 안내와 재시도 가능 상태, 중복 시작 방지, Main 1회 로드, 플레이어·카메라·EventSystem 각 1개, Intro UI 제거를 확인했다.
- Main 진입 후 커서는 숨겨지고 잠겼다. Main의 기존 `사격 모드 없습니다.` 오류는 이번 작업에서 수정하지 않았다.
- 별도 실행에서 종료 버튼 위치의 UI Raycast와 포인터 클릭 이벤트를 검사했고, 이후 Play 모드가 종료된 것을 확인했다.
- 실제 1920×1080 Game View를 캡처해 검토했다. 제목 영역 높이가 폰트 줄 높이보다 작아 잘리는 문제를 찾아 190으로 조정한 뒤 제목 표시를 재확인했다.
- 검증은 버튼 이벤트를 코드로 호출한 방식이다. 운영체제의 실제 마우스·키보드 입력이나 배포 실행 파일의 종료는 검증하지 않았다.
- 1단계 전체 완료는 아니다. 실제 플레이어 상호작용 UI 연결 복구, 직접 조작과 스폰 확인, 왕복 3회 검증이 남아 있다. 인벤토리는 사용자 요청에 따라 이후 단계로 유지한다.

### 사용자 요청에 따른 Intro 단순화

후속 요청에 따라 중앙 제목과 기본 `게임 시작`·`종료` 버튼만 남겼다. 배경 장식, 영문 문구, 설명과 조작 안내, 로딩 안내 텍스트 오브젝트를 제거했다. 시작·종료 스크립트와 버튼 참조는 유지했다. 실제 Game View에서 단순화한 화면을 확인했다. 앞의 로딩 안내 텍스트 검사는 이전 화면에 대한 기록이며, 현재 화면에서는 로딩 중 버튼 비활성화로 중복 실행을 방지한다.

## Main 상호작용 UI 복구와 왕복 검증

- Main 플레이어의 Missing Script가 기존 PlayerInteractUI임을 저장된 씬에서 확인했다. Unity Editor API로 해당 누락 컴포넌트 하나를 제거하고 현재 PlayerInteractUI를 연결했다.
- 기존 `InteractBtn`, 그 하위 `Text (Legacy)`, 기존 `Slider`를 연결했다. UI 디자인과 게임 스크립트 로직은 변경하지 않았다.
- 씬 저장 과정에서 현재 Min의 ScenePortal에 존재하지 않는 예전 `interactKey` 직렬화 값이 Unity에 의해 정리됐다. 현재 포털 코드는 기존대로 E키를 사용하며 목적지와 감지 거리는 유지됐다.
- Unity Play 검사 41개 통과: 실제 Main 플레이어 UI의 채집 안내, 진행바 증가, 반복 시작 차단, 범위 이탈 시 표시 정리, 치료 진행바와 비활성화 시 정리, Main↔Collection 왕복 3회.
- 왕복의 여섯 지점에서 동일한 플레이어·PlayerInteractUI 인스턴스와 유효한 텍스트·슬라이더 참조가 유지됐고, 카메라와 EventSystem은 각각 1개였다. 양방향 포털 안내도 각 왕복 후 표시됐다.
- 검사 실행 구간의 Error/Exception 로그는 없었다. Play 시작 직후의 기존 무기 설정 문제 해결까지 뜻하지 않는다.
- 검증은 실제 Unity 프레임·콜라이더·원래 플레이어/UI를 사용했지만 선택·행동 시작·포털 로드 함수를 코드에서 호출했다. 실제 E키 입력 및 이동·카메라 조작감 검증은 아직 남아 있다.
- 임시 검사 오브젝트는 제거했고 Play를 종료했다. 자원 인벤토리는 추가하지 않았다. 작업 전 백업과 비교하여 이번에 바뀐 Assets 파일은 `01_Main.unity`뿐임을 확인했다.
